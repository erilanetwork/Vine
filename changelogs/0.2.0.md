# Vine 0.2.0

Unreleased.

## Server owner tools

- `/vine config reload` reads `vine.toml` again without a restart. Routing, servers, MOTDs, icons, permissions, maintenance and the whitelist apply right away; settings that only apply at start are listed so nothing changes silently.
- Health checks ping every backend on `[health] interval_secs`. A backend that misses `unhealthy_after` checks in a row counts as down: new players go to the next server in line, `/server` shows it as offline and refuses to switch there, and `/status` shows each backend's ping.
- Backends take an optional `max_players`. `/server` into a full backend puts the player in a queue and moves them over once a slot opens, with `vine.queue.priority` and `vine.queue.bypass` for staff. `/queue` shows the player's place and `/queue leave` gives it up.
- `/ban`, `/unban`, `/banip`, `/unbanip`, `/banlist` and `/kick`. Bans can be temporary (`/ban Steve 1d griefing`) and are stored in `banned-players.json` and `banned-ips.json`. Banned addresses are refused before the Mojang session check.
- `/whitelist on|off|list|add|remove`, stored in `whitelist.json`, with `vine.whitelist.bypass`.
- `/maintenance on|off` with its own server list text and a red version label. Players without `vine.maintenance.bypass` are kicked and kept out.
- `/maintenance` and `/whitelist` write their switch back to `vine.toml` without touching the rest of the file, comments included.
- Prometheus metrics at `[metrics] bind_address`: players per server, backend health and ping, queue lengths, plugins and counters for connections, logins, rejected logins and switches.

## Plugins

- `vine-plugin-sdk`, a Rust SDK for writing plugins, with `examples/hello-plugin` showing events, commands with tab completion and translations.

## Removed

- The Pterodactyl egg. Panels can still run the release binaries and set the port through `VINE_BIND_ADDRESS`.

## Quality

- End to end tests run the proxy against a fake backend and cover the server list, logins, bans, the whitelist, maintenance and metrics.
- CI builds the example plugin for `wasm32-wasip2` and loads it into the real plugin host.
